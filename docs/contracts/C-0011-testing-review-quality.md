# C-0011 Testing, Review and Quality Tools

| Field | Value |
|---|---|
| Status | Draft |
| Version | 0.1 |
| Date | 2026-10-28 |
| Owner | recelilious |

This contract defines how Paneport is tested, which tools check it, how changes are reviewed, and what continuous integration runs.

## 1. Test levels

| Level | What it covers | Tools | Runs on |
|---|---|---|---|
| C# unit tests | Paneport.Core, and Paneport.Steam with fakes | xUnit v3 | Windows and Linux in CI |
| UI tests | View models, and views rendered headless | Avalonia.Headless with xUnit v3 | Windows and Linux in CI |
| Native unit tests | Parts of the native host that also build for macOS: queues, governor logic, configuration parsing | CTest with a small assertion header kept in the repository. Two sanitizer builds: AddressSanitizer with UndefinedBehaviorSanitizer for all native tests, and ThreadSanitizer for the concurrent code. | macOS in CI |
| Interface conformance | Struct sizes and member offsets match between C and C# (C-0005 section 5) | `tests/Paneport.Interop.Tests`, run against the host's test build | macOS in CI, and on the device |
| Compatibility data | Every `*.json` file in `compat/titles/` matches the title schema; the file-name, launch and allow-list rules of C-0008 section 5 and the rating rule of C-0008 section 3 hold; `compat/ios-builds.json` matches its schema | A C# tool in `tools/` | CI |
| Device tests | The phase gates, sample programs such as the Direct3D triangle, and smoke tests of real games | The test app in `tests/device`, with scripted steps where possible and written steps otherwise | recelilious's iPhone |

Rules:

- **Fakes, not mocks.** Tests use hand-written fakes. Mocking libraries are not used.
- **Synthetic test inputs.** Test inputs are produced by our own code. PE files for the classifier of C-0007 section 5 are generated by a tool in `tools/` or built from our own source in `tests/`. No game file, `steam_api` library, Microsoft or Valve binary, captured Steam traffic, real depot manifest, token, Steam ID or other account data is ever committed.
- **Regression tests.** A bug fix comes with a test that fails without the fix, wherever that is possible.
- **New APIs.** New public APIs in Paneport.Core and Paneport.Steam come with tests.
- **No coverage target.** There is no coverage percentage target.
- **Device metrics.** Device tests that render frames record the median and 1% low frame rates. Every device test records the peak memory footprint and the thermal state over time, from the native host's counters and `pp_memory_get_budget` (C-0005). The results go into an evidence record (C-0012).

## 2. Static checks

| Check | Tool |
|---|---|
| C# formatting | `dotnet format --verify-no-changes` |
| C# analysis | .NET analyzers with warnings as errors, including the AOT and trimming analyzers |
| Trimming of dependencies | A trimmed test app that roots our libraries, published with every trimming warning shown |
| Native formatting | `clang-format` in check mode, on `src/` and `tests/` only |
| Native analysis | `clang-tidy`, and compiler warnings as errors (C-0010 section 3) |
| License headers and license texts | REUSE (`reuse lint`), once the C-0003 change proposed alongside this contract is accepted |
| Secrets | The gitleaks command-line tool, from a pinned release. Not the gitleaks GitHub Action, which has been under a proprietary license since version 2. |
| Personal data and forbidden files | A tool in `tools/` that fails on UDIDs, ECIDs, serial numbers, team identifiers and application-identifier prefixes, e-mail addresses, Steam IDs, IP addresses, tokens, depot keys, manifest request codes and local paths in `docs/evidence/`, `compat/` and `tests/`, and on any tracked file with an extension that C-0002 section 6 forbids. Device model identifiers are allowed. |
| Links in Markdown | lychee |
| Dependency licenses | A tool in `tools/` that reads every `packages.lock.json` (direct and transitive packages), the package directives of the file-based tools, `.gitmodules` and `eng/toolchain.json`, and fails on anything missing from the register in C-0003 |

Claude runs the personal-data, secrets and format checks locally before every push, because CI runs only after the push.

## 3. Review

- A change reaches `main` in one of three ways: recelilious merges it after review; recelilious asks for it to be committed directly to `main` (C-0002 section 2); or it falls under a standing exception that recelilious has accepted (C-0012 section 2).
- A branch is merged only after the `dotnet`, `native`, `ios` and `checks` jobs have passed on its last commit, unless a standing exception in C-0012 section 2 names fewer jobs.
- Before handing a change over, Claude checks it against the definition of done in C-0012 section 1. The pull request lists any check that needs macOS and has not yet passed in CI, and marks device behavior as "not yet verified on device".
- Claude may also run Claude Code's `/code-review` on the change. Each finding is either fixed or answered in the pull request.
- Review comments are resolved before merging.

## 4. Continuous integration

GitHub Actions runs these jobs on every pull request and every push.

| Job | Runner | Steps |
|---|---|---|
| `dotnet` | Windows and Ubuntu | Locked restore, build, tests and format check of the solution filter `eng/ci.slnf`, which leaves out Paneport.iOS, `tests/device` and `tests/Paneport.Interop.Tests`; publish the trimmed test app. |
| `native` | macOS | clang-format and clang-tidy; configure, build and run CTest twice, with the CMake presets `asan-ubsan` and `tsan`; build the host's test library and run `tests/Paneport.Interop.Tests` against it. |
| `ios` | macOS | C-0009 stages 1 to 4 without signing: the forks, the native host, the Dock host and Paneport.iOS. |
| `checks` | Ubuntu | REUSE, gitleaks, personal-data and forbidden-file check, lychee, compatibility data, dependency licenses. |
| `release` | macOS | Runs only for a `v*` tag. Builds and packages the release as C-0009 section 6 describes. |

- While the repository is public, standard GitHub-hosted runners are free. If it becomes private, macOS minutes beyond the account's included minutes are billed.
- recelilious decides whether the `ios` job runs on every pull request or only before merging, once its run time is known.
- Device tests cannot run in CI. They are recorded as evidence instead (C-0012).

## 5. Libraries and tools to register under C-0003

These are added to the C-0003 register by the change proposed alongside this contract. Each needs recelilious's approval like any other change to C-0003. The proposal also registers CMake, Meson, Ninja, Xcode, llvm-mingw and its runtime libraries.

| Package or tool | License | Use |
|---|---|---|
| xunit.v3 | Apache-2.0 | Test framework |
| Avalonia.Headless.XUnit | MIT | Headless UI tests |
| CommunityToolkit.Mvvm | MIT | MVVM source generators (C-0010) |
| gitleaks (command-line tool) | MIT | Secret scanning, CI only |
| REUSE tool | GPL-3.0-or-later | License header checks, CI only |
| lychee | MIT OR Apache-2.0 | Link checks, CI only |
| clang-format, clang-tidy | Apache-2.0 WITH LLVM-exception | Native style and analysis, CI only |

Registered as under review, and not used until recelilious decides:

- **JsonSchema.Net.** The source is MIT, but its NuGet packages ship under the json-everything Open Source Maintenance Fee agreement. If that is not acceptable, the compatibility check uses a validator whose package is under an allowed license.

Not allowed: FluentAssertions 8 and later. They are under Xceed's proprietary Community License, which is free only for non-commercial use (it counts open-source development as non-commercial) and needs a paid license for any commercial use. That makes it a non-commercial-only license, which C-0003 section 5 forbids.
