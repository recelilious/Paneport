# Design

This folder holds Paneport's design documents.

| File | What it is |
|---|---|
| [development-plan.md](development-plan.md) | How development is split into Large, Medium and Small stages, how a stage session works, the decisions recelilious makes along the way, and the full stage map with its dependencies. |
| [stages/](stages/README.md) | One brief per Large stage, holding the detailed briefs of its Medium and Small stages. Stage sessions keep each stage's status and session log there. |
| [solution-and-build.md](solution-and-build.md) | How the .NET solution is laid out and built: the projects and their dependency rules, build properties, code style, packages and lock files, tests, license headers and CI. The first design record of each .NET project. |
| [repository-checks.md](repository-checks.md) | How the repository rules are checked: the personal-data scanner, the license checker and the toolchain checker in `tools/`, the trimmed test app, the pinned CI tools, and the `dotnet` and `checks` jobs. |
| [release-engineering.md](release-engineering.md) | How app bundles and releases carry what C-0009 section 6 asks for. So far the third-party notices: their place in the bundle and the format of their index, the notices generator and its rules, the attribution mapping, where the license texts come from, the step of the `ios` job, and the source files that tools share. |
| [app-shell.md](app-shell.md) | The app shell in Paneport.Core, Paneport.UI and Paneport.Desktop: the domain model, the service interfaces and who implements them, the settings, navigation and view matching, threading, the desktop head's fakes and sample titles, and the tests. |
| [dev-environment.md](dev-environment.md) | Where each part is built and how a machine is set up for it: the Windows workstation, a local Mac with `eng/mac/bootstrap.sh`, the `ios` CI job that stands in for the Mac, and the iPhone. The toolchain pins of the iOS build and why they were chosen. |
| [compat-db.md](compat-db.md) | The compatibility database core: the title schema mapped to C-0008, the bundled and device layers and their rules, how the layers merge, the launch rule, reading and writing title files, the device layer store, which rules the code enforces with their tests, and the compatibility check that CI runs on the title files, with the rating it computes. |
| [native-host.md](native-host.md) | The native host: its public headers and their conventions, the life cycle and the main-thread rule, the lock-free event queue, the event thread, the log pipeline, the memory budget and the Game Mode level, the crash record and its byte layout, the test builds, the CMake presets and the framework, and the native checks. |
| [interop.md](interop.md) | Paneport.Interop: the library name per target, the bindings with runtime marshalling off, the safe API and its exceptions, the callbacks, the layout conformance test and how it measures C# offsets, and the tests on macOS. |
| [forks.md](forks.md) | The fork repositories of Wine, FEX-Emu and DXMT: the upstream versions they start from, what their integration branches carry, how their branches and this repository's submodule pointers move, the upstream rule, the build tools of the Mac that they need, the first fork targets in CI, and the plan for caching fork builds. |
| [ios-app-head.md](ios-app-head.md) | The iOS app head and the device test flavor: the scene and view tree with Avalonia hosted in its own root view controller, startup, the host adapter, the settings file and the keychain token store, the build stamp, Info.plist and entitlements and how the app reads them, Diagnostics, the storage bootstrap, crash records and the log, the developer menu, and the ad-hoc signing, packaging, check and scan of the `ios` job. |
| [signals.md](signals.md) | The signal dispatcher: installing it in `pp_init` and chaining to the runtime's handler, the routes and the lock-free registries with their capacities, Mono's crash chaining and the last-resort handler, the guest and probe handlers, alternate stacks and the installed check, the Mach thread control helpers, the stress harness of the signal gate with its verdict and hang threshold, the tests and the sanitizer settings. |
| [jit.md](jit.md) | The JIT provider: the app side of the JIT request protocol with its iOS and macOS backends, the states and their transitions, the pool's size and regions of 128 MiB, the debugger flags and the broker-recognition rule, the commands and the dual mapping, the verification probe, the threads and the JIT group of the host interface, the list of verified iOS builds and its check, and the tests. |
| [jit-broker.md](jit-broker.md) | The JIT broker script that StikDebug runs and the request that names it: what the contracts ask of the script, what StikJIT's `INTEGRATION.md` documents and leaves out, recelilious's decision of 2026-11-23 that the request names StikDebug's built-in `universal.js` (C-0006 1.1), and the URL that the app builds. |
| [runtime-macos-harness.md](runtime-macos-harness.md) | ARM64EC Wine with FEX on arm64 macOS: how Wine and FEX's module are built, what the forks must add on Apple silicon, the Win32 test programs, the harness that runs them and checks their output, the runner and its template prefix, the `runtime` job and its caches, and the third-party code that the builds compile. |
| [single-process-wine.md](single-process-wine.md) | Wine in one process, as an iOS app needs it: the session's threads, the wineserver as a library on a host thread, the start of a process on a thread of its own, the replacement of every signal that Wine uses, thread control by Mach calls, the end of a process without `exit`, the template prefix with the boot step and the drive letters, the helpers that are not started, the address-space plan and the process-wide state. |
| [runtime-ios.md](runtime-ios.md) | The runtime on arm64 iOS: the cross-builds of Wine's Unix side, FEX and the host, their frameworks and the loader's search paths, the JIT pool's hand-off to FEX, PE code in the pool, address space, x18 and TLS, the template prefix and its installer, guest console capture, and the bundle check. In progress with M4.4. |

Component design documents are added here as stages create them (C-0012 section 1). Each one lists the public sources it consulted (C-0001 section 6).
