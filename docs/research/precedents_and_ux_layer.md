## KQ1. iPhone/iPad precedents 2024–2026: has anyone run Windows games on a jailed iPhone/iPad (Wine + x86 translation + JIT)? What about UTM (QEMU TCG) and iSH?

### Takeaway
Yes — publicly and very recently. **Madeira** (Will Faust, first public release 0.1.0 on 2026-10-01, GPL-3.0-or-later) runs unmodified x86-64 Windows games on non-jailbroken iPhones using **ARM64EC Wine 11.4 + FEX-Emu + DXMT (D3D9/10/11→Metal) + an own D3D12→Metal runtime**, all in **one iOS process with wineserver as a thread**, with JIT obtained via a StikDebug-style debugger attach. Two forks (**BCD**, **WiniOS**) add Steam/GOG/Epic launchers. Before Madeira, the only "Windows on iPhone" precedents were full-system QEMU emulation (UTM/UTM SE — 20-minute boots, useless for games) and user-mode Linux emulation (iSH — architectural precedent for multi-process-in-one-process, interpreter-only).

### Cited Findings

**Madeira (the key precedent)**
- Madeira "runs Windows PC games on an iPhone without a jailbreak"; games "run as they are, unmodified, inside a single iOS app"; author calls it "an active research project" with "rough edges". Stack: FEX-Emu translates x86/x86-64 at runtime; **Wine 11.4 built for ARM64EC** so Wine itself runs natively and only game code is translated; **32-bit games via WoW64**; **DXMT** for D3D9/10/11 on Metal; **madeira-d3d12**, its own D3D12-on-Metal implementation converting DXIL at runtime with Apple's **Metal Shader Converter**. "Everything runs in one process, because iOS apps cannot start other programs. Wine's server runs as a thread." — [Madeira README](https://github.com/willfaust/madeira)
- JIT: "iOS allows JIT only while a debugger is attached. Madeira uses StikDebug or its built-in StikJIT helper. On iOS 27, the built-in helper can pair with the iPhone without a computer." Requires iOS 26+ ("the only version Madeira currently runs on reliably"); "Development happens on recent Pro iPhones." — [Madeira README](https://github.com/willfaust/madeira)
- Features: game library with artwork/search, a "Windows desktop session", **Steam sign-in, owned-library browse/install/update, launch through Valve's Windows Steam client via "Madeira Dock"**, Steam Cloud saves with conflict handling; **input: Bluetooth controllers via XInput, customizable on-screen touch controls, keyboard/mouse/trackpad passed through as real input**; media via FFmpeg + VideoToolbox + AudioToolbox. — [Madeira README](https://github.com/willfaust/madeira)
- Install: sideload IPA with Apple ID via SideStore/AltStore/Sideloadly/Plume; enable JIT in-app; Settings must show both "JIT" and "Memory+" green. "Free Apple ID signing expires after 7 days... Games and saves are kept across reinstalls. Because JIT requires a debugger, the app cannot be offered on the App Store." — [Madeira README](https://github.com/willfaust/madeira)
- Known limitations in README: 64-bit games often need Microsoft VC++ runtime, **not bundled** (user supplies); building requires Madeira's **own forks of FEX, Wine, DXMT, madeira-dock — upstream checkouts will not build**; "The forks contain a lot of AI-assisted work. The README asks users not to send changes from these forks upstream to FEX-Emu, which does not accept AI-generated code." — [Madeira README](https://github.com/willfaust/madeira)
- Licenses: Madeira GPL-3.0-or-later **with a "Madeira Converter Exception"** permitting use with Apple's Metal Shader Converter; Wine fork LGPL-2.1+; FEX and DXMT forks: upstream MIT, Madeira changes GPL-3.0+; rpmalloc fork 0BSD upstream. Repo snapshot: 1,027 commits, 2.9k stars, 356 forks, 80 open issues. Credits: Nick (32-bit support, library, Dock), Jfishin (Steam sign-in), Jesse (Cloud saves), Dan Perks (in-app JIT, pairing without computer). — [Madeira README](https://github.com/willfaust/madeira)
- Release timeline (year not shown on page; corroborated as 2026 by press): **0.1.0 (01 Oct, first release)** — FEX + Wine 11 ARM64EC + DXMT, D3D12 "natively", fastsync default; lists iOS 17+ but designed for iOS 26. **0.1.1 (02 Oct)** — free-Apple-ID installs on iOS 26 launch again; loader/memory fixes for "unaligned data sections, missing relocation data, missing AppData\LocalLow". **0.1.2 (03 Oct)** — D3D9/11 work on iOS 26 again: "shader library now targets Metal 3.1 instead of 4.1, which iOS 26 couldn't load". **0.1.3 (03 Oct)** — bundled JIT helper (pair on-device on iOS 27, import pairing file on iOS 26), Play button auto-enables JIT; Cuphead, Nine Sols, Hades II now run; **controller can act as keyboard+mouse per game; DirectInput per-game toggle**; known issue: LocalDevVPN can't connect with Wi-Fi and cellular both off. — [Madeira releases](https://github.com/willfaust/madeira/releases)
- Press (2026-10-03): "Madeira 0.1.0 shipped October 1"; dev device iPhone 13 Pro (A15); Thumper and ULTRAKILL playable; Marvel Cosmic Invasion reaches gameplay with unreliable controls; "A developer post claims Red Dead Redemption 2 runs at '30+ FPS on an iPhone 18 Pro'" (not independently verified); ~1,200 stars/214 forks at that time. — [iThinkDiff 2026-10-03](https://www.ithinkdiff.com/madeira-windows-pc-games-iphone-no-jailbreak/)
- Independent review (dated 2026-09-11, when the project was described as "weeks old"): playable = Thumper, ULTRAKILL; other titles "reach gameplay only at low frame rates"; **Cyberpunk 2077 not supported** despite headlines; "RAM and sustained thermals are the main limits"; StikDebug "needs a pairing file generated on a computer. That file stops working after an iOS update or device reset"; "iOS 26.4 removed the airplane-mode trick for enabling JIT offline"; StikDebug "works with only a handful of apps on iOS 26.6 and iOS 27"; paid developer account extends signing to one year; **"Each reinstall requires reconnecting the pairing file and restarting the loopback VPN and debugger."** — [HeldGames guide](https://heldgames.com/guides/madeira-windows-games-iphone)
- Later press (2026-10-12): Madeira X account claims RDR2 "30+ FPS" on iPhone 18 Pro; Far Cry 3 60 FPS on iOS 27 (clip by developer "Majd"); a separate unreleased project "Vapor" claims GTA V 66–80 FPS avg at 1080p DX11 on iPhone 18 Pro Max (work in progress, unvalidated); Cyberpunk 2077 ~30 FPS at ~900p on iPhone 17 Pro Max using "nearly all 12 GB RAM" — but that was the **native macOS build through an unreleased macOS→iOS translation layer, not x86 emulation**; iPad Pro (M5) on iPadOS 27 users filed Madeira 0.1.3 bug reports (some Unity games crash). — [iThinkDiff 2026-10-12](https://www.ithinkdiff.com/windows-pc-games-iphone-ipad-no-jailbreak-madeira/)

**BCD (fork of Madeira)**
- "Windows games on iPhone and iPad", alpha ("Many games run, many do not yet"); fork of Madeira; Wine + FEX (pinned submodule) + DXMT for D3D9/10/11 + own D3D12 runtime with Metal Shader Converter; rpmalloc; mentions a "swap tier". JIT: on iOS 26+ with **A15/M2 or newer**, built-in helper paired once on device, or StikDebug; on iOS 18 or older chips, StikDebug with "Always Run Scripts". Credits Dan Perks for "in-app JIT without StikDebug". — [BCD README](https://github.com/thebcd69/bcd-games)
- Steam: password+Steam Guard or QR sign-in, library/downloads/updates/file checks/Cloud saves, DLC selection, **background downloads on iOS 26**; "BCD Dock runs Valve's own Steam client without its window"; GOG (early) and Epic (early; warns before install if a game uses Easy Anti-Cheat or another launcher). — [BCD README](https://github.com/thebcd69/bcd-games)
- Device floor: iOS 18+, A13+; **A14+ required for geometry shaders/tessellation; A17 Pro or M-series recommended for heaviest games; A12 and older unsupported** ("their GPUs lack what Direct3D needs"); "Each game needs its full install size on the device." — [BCD README](https://github.com/thebcd69/bcd-games)
- Performance claims (self-reported): showcase videos of Crysis 2 Remastered and GTA V Legacy on **iPhone 17 Pro Max**; FF VII Remake Intergrade low/900p/30 FPS on M5 iPad Pro; Kingdom Hearts III highest settings mostly 60 FPS on M5 iPad Pro; **Metro 2033 Redux 60 FPS (tessellation off) on iPhone 17 Pro**; Ratchet & Clank: Rift Apart ~20 FPS with glitches. Built-in tuned settings for God of War, Ghost of Tsushima, Horizon ZD/FW, RDR2, GTA V/IV, CS2, Crysis Remastered trilogy. — [BCD README](https://github.com/thebcd69/bcd-games)
- Input: DualSense (rumble, adaptive triggers, light bar), Xbox, Switch Pro, MFi; keyboard+mouse; controller-to-keyboard/mouse mode; on-screen touch controls with editor; touch gamepad survives in-game keyboard. Distribution via **AltStore/SideStore source JSON** (`https://thebcd69.github.io/bcd-games/source.json`) for updates, or IPA via SideStore/AltStore/LiveContainer; first launch wizard: JIT, LocalDevVPN, Steam, runtimes; free Apple ID "limits active sideloaded apps to three" — suggests LiveContainer, GetMoreRam (Increased Memory Limit entitlement), StikDebug. VC++ runtime and Wine Mono downloaded at runtime after license acceptance. License GPL-3.0 with Madeira Converter Exception; BCD's own files GPL-3.0-only with attribution terms (GPL §7). — [BCD README](https://github.com/thebcd69/bcd-games)

**WiniOS ("Madeira GameHub")**
- Same core (FEX-Emu, ARM64EC Wine "in a single Mach process, with an in-thread wineserver", DXMT) plus "a custom iOS driver, **winios.drv**, handling touch controls, gamepads, and a virtual desktop" and a GameHub-style console launcher; claims Thumper, ULTRAKILL, Hollow Knight, Vampire Survivors "and other DX11 titles" playable; D3D11 test cube at full display refresh; GPL-3.0-or-later; dev on A15 iPhone 13 Pro; 216 commits. — [WiniOS README](https://github.com/yanyantukebo1224/WiniOS)

**Not a precedent: "winlator-ios"**
- The only repo named winlator-ios (Mobimi) is a Vietnamese Linux-VM dev-environment project whose README says the build "has no Linux engine yet"; no evidence of a Winlator port. — [search summary citing Mobimi/winlator-ios](https://github.com/Mobimi/winlator-ios)

**UTM / UTM SE (QEMU) as the earlier "Windows on iPhone"**
- UTM iOS variants: UTM.ipa (sideload, JIT "may need a JIT enabler", no hypervisor), UTM.HV.ipa (TrollStore, hypervisor on M1 iPad+), UTM.SE.ipa (no JIT, "slower interpreter"; "will run much slower"); semi-tethered JIT via AltJIT/PC, another iOS device, or StikDebug + on-device VPN. — [UTM iOS install docs](https://docs.getutm.app/installation/ios/)
- July 2024: NTDEV booted **tiny11 (Windows 11 x86) on iPhone 15 Pro with UTM SE: ~20-minute boot**, virtual 1 GHz single-core, 2 GB RAM. — [Gigazine 2024-07-24](https://gigazine.net/gsc_news/en/20240724-windows-11-runs-iphone-15-pro); [TechSpot thread](https://www.techspot.com/community/topics/the-iphone-15-pro-can-run-windows-11-if-you-can-tolerate-the-20-minute-boot-time.287031/)
- Windows XP on UTM SE: install up to 2 hours plus ~30 min boot; sideloaded JIT UTM improved it. — [Windows Central](https://www.windowscentral.com/software-apps/an-avid-tech-youtuber-gets-windows-xp-to-run-on-the-iphone)
- Windows 11 **ARM** on iPad Air M2 with JIT-enabled UTM (EU only via AltStore PAL + StikDebug) ran "largely without any problems" (no benchmarks); without JIT it "wouldn't even boot" — article 2025-04-28. — [heise](https://heise.de/-10364121)
- Why unsuitable for games: UTM SE "uses a threaded interpreter which performs better than a traditional interpreter but still slower than JIT"; App Store policy forbids JIT. — [UTM GitHub](https://WWW.GITHUB.COM/utmapp/UTM); [9to5Mac 2024-06-09](https://9to5mac.com/2024/06/09/apple-blocks-pc-emulator-utm-app-store/)

**iSH (architectural precedent)**
- "Linux shell on iOS using user-mode x86 emulation and syscall translation"; its execution engine is "not quite a JIT" — an array of function-pointer "gadgets" each tail-calling the next (threaded code), ~3–5x over switch dispatch, mostly assembly with "almost no comments"; distributed on App Store/TestFlight. — [iSH README](https://github.com/ish-app/ish); [ish.app](https://www.ish.app)

### Inferences
- The single-process constraint (no fork/exec on iOS) is the defining architectural fact: Madeira/BCD/WiniOS all run wineserver as a thread and every Windows "process" inside one Mach task; iSH did the same for Linux processes years earlier. A new runtime must design its process model around this from day one (Wine's multi-process assumptions, wineserver IPC, CreateProcess semantics).
- The only working graphics path demonstrated on iOS is **D3D→Metal directly** (DXMT, own D3D12 runtime via Metal Shader Converter) — no project demonstrated DXVK/MoltenVK on iPhone. Madeira's 0.1.2 note (Metal 3.1 vs 4.1 shader library) shows the iOS Metal version gating is a live compatibility hazard.
- Demonstrated performance tier on A15–A19-class phones: 2D/indie DX11 titles playable; mid-2010s AAA (Metro 2033 Redux, Far Cry 3) at 30–60 FPS claims; modern AAA (RDR2) ~30 FPS claims on iPhone 18 Pro; nothing on Cyberpunk through emulation. These are developer/X claims, not reviewed benchmarks.
- "Memory+" in Madeira almost certainly corresponds to the `com.apple.developer.kernel.increased-memory-limit` entitlement (BCD names GetMoreRam explicitly) — see KQ5 on the ~6 GB cap.

### Gaps
- No reviewer has published FPS benchmarks for Madeira/BCD on a specific iPhone 17 Pro under controlled settings; all numbers are self-reported or X-posted.
- I found no source describing how Madeira presents the Windows display (own Wine display driver vs X server); WiniOS names `winios.drv`, implying a custom winex11-equivalent driver, but Madeira's README is silent.
- Madeira's exact first-commit date is unknown (press says "weeks old" on 2026-09-11; first tagged release 2026-10-01).

## KQ2. Android precedents (architecture only): Winlator and forks, GameHub, GameNative, Pluvia, Mobox/Box64Droid, ExaGear, Xiaomi WinPlay, Hangover

### Takeaway
The Android ecosystem converged on **Wine (9.x/10.x) + Box64 (and increasingly FEXCore with ARM64EC) + Mesa Turnip/Vulkan + DXVK/VKD3D, presented through an in-app X server**, with newer forks bypassing X11 ("Direct Android Compositing") and GameSir's closed-source GameHub adding FSR 3 frame-gen marketing. Snapdragon 8 Elite (Adreno 830) remains unreliable with Turnip as of mid-2026; community FPS claims (720p, low–medium) range from 60 FPS (RE2, God of War) to 7–10 FPS (Witcher 3). Steam support is either the real Windows Steam client inside the prefix or a reimplemented client (Pluvia → GameNative) that downloads depots directly.

### Cited Findings

**Winlator (upstream, brunodev85 / Bruno Sousa)**
- "Android application for running Windows applications with Wine and Box86/Box64"; components: Wine, Box86/Box64 (ptitseb), Mesa (Turnip/Zink/VirGL), DXVK, VKD3D, CNC DDraw, glibc patches (Termux Pacman); submodules vortek, gladio, android_alsa; **LGPL-2.1**; tips mention Box64 preset changes, `MESA_EXTENSION_MAX_YEAR=2003`, Unity exec args; per-shortcut settings; "Force Fullscreen" for low-res games. — [Winlator README](https://github.com/brunodev85/winlator)
- Release notes (years not shown; 11.2 = latest): **11.2 (19 Aug)**: save-memory option for Steam games, "XInput extension for raw input", foreground-service option, Turnip v26.2.0 (whitebelyash), Box64 v0.4.4, Vortek mipmap/Xclipse improvements, Gladio OpenGL 1.x/ARB. **11.1 (12 Jun)**: reworked gamepad input, D7VK, gamepad model selection, Steam Legacy Start Menu. **11.0 (26 Sep)**: Wine 10.10, multiple controllers + vibration, Gladio via GLES, HUD mode, install DXVK/WineD3D/VKD3D from file, Box64 v0.4.0, Turnip 26.1.0 devel with A8XX patches. **10.1 (08 Jul)**: MIDI, virtual CD-ROM (X:) via libcdio, PiP, XServer black-screen fix, Box64 0.3.6, Turnip 25.1.0; Vortek async pipeline creation. **10.0 (28 Feb)**: native glibc, pointer capture, "direct rendering on XServer and Turnip Vulkan WSI X11", wine-9.2-custom. **9.0 (03 Jan)**: Vortek (experimental), component installer. **8.0**: screen effects, DirectInput/XInput selection, Box64 0.3.0, DXVK 2.4. **7.0**: experimental WoW64 mode, VKD3D. — [Winlator releases](https://github.com/brunodev85/winlator/releases)
- History: first released v1.0.0 August 2023; v10.0 2025-02-28; v10.1 2025-07-08; v11.0 beta 2025-09-26; development paused late April 2025 and resumed May 2025 (reasons given inconsistently: harassment vs security). Each container is an isolated Wine prefix; RootFS moved from Ubuntu Focal to native glibc in 10.0; FSR built in since 7.0; Vortek described as "an adapter to Android graphics drivers". — [Grokipedia: Winlator](https://grokipedia.com/page/Winlator) (secondary; unverified)
- Secondary guide dates: 9.0 2025-01-03, 10.0 2025-02-28, 10.1 2025-07-08, 11.0 2025-09-26, 11.1 2026-06-12, 11.2 beta 2026-08-19. — [tech-insider setup guide](https://tech-insider.org/ie/winlator-setup-2026/) (low-quality secondary; consistent with GitHub day/month)
- Input controls: on-screen BUTTON / D_PAD / RANGE_BUTTON / STICK (dead zone, sensitivity) / TRACKPAD (cursor with acceleration); bindings to keyboard key, mouse button, gamepad button/axis; profiles saved as `.icp` ("ControlsProfile") with name, ID, cursor-speed multiplier, element list, optional external-controller bindings; **element positions stored as fractional screen coordinates**; editor is a transparent canvas over the running app; bundled per-genre profiles; export to Downloads. — [Winlator input-controls docs (mintlify mirror)](https://mintlify.wiki/brunodev85/winlator/controls/input-controls)
- Troubleshooting: "Poor frame rates and stuttering are the most common complaints"; fixes = Box64 performance preset, `mesa_glthread`, WINEESYNC, switch WineD3D→DXVK; use 64-bit exe to bypass Box86. — [Winlator troubleshooting (mintlify mirror)](https://mintlify.wiki/brunodev85/winlator/advanced/troubleshooting)

**Hangover (Linux ARM64, the Wine-side reference design)**
- Runs x86_64/x86_32 Windows apps on aarch64 Wine using "emulator DLLs to emulate only the application you want to run"; Windows/Wine system functions run **outside** the emulator; nothing Unix-side is emulated — possible because of Wine's WoW64. 64-bit: **ARM64EC ABI + FEX (libarm64ecfex.dll)**; 32-bit default **Box64 as PE (wowbox64.dll)**, optional libwow64fex.dll; QEMU removed; LGPL-2.1; started 2016 by André Zwing and Stefan Dösinger; DXVK needs Vulkan 1.3 features "many ARM64 devices may lack". — [Hangover README](https://github.com/AndreRH/hangover)
- Hangover 11.0 released 2026-01-13: "pairs Wine with either the FEX-Emu or Box64 emulators", drops QEMU "since the FEX and Box64 emulators are superior". — [Phoronix](https://phoronix.com/news/Hangover-11.0-Released)

**Pain points documented**
- Shader stutter: Unreal Engine games → DXVK-Async recommended; crashes in some DX titles; input lag; battery drain. — [Grokipedia: Winlator](https://grokipedia.com/page/Winlator)
- DXVK 3.0 (June 2026) moved shader compilation fully to worker threads and caches intermediate data on disk (`DXVK_SHADER_CACHE_PATH`) — relevant to stutter if a Vulkan path were ever used. — [GamingOnLinux](https://www.gamingonlinux.com/2026/06/dxvk-3-0-brings-lots-of-improvements-for-windows-games-on-linux-steamos/comment_id=296863)
- Anti-cheat: BCD warns Epic games with Easy Anti-Cheat cannot run; GameNative cannot run games needing external launchers. — [BCD README](https://github.com/thebcd69/bcd-games); [Notebookcheck GameNative](https://www.notebookcheck.net/GameNative-promises-hassle-free-Windows-game-emulation-on-Android.1039653.0.html)
- .NET: "Applications that need .NET Framework may need Wine Mono"; VC++ runtime must be fetched separately for license reasons (Madeira/BCD). — [Winlator-Ludashi](https://github.com/StevenMXZ/Winlator-Ludashi); [BCD README](https://github.com/thebcd69/bcd-games)

### Inferences
- Android projects spend enormous effort on the GPU driver layer (Turnip builds, Vortek, Zink, AdrenoTools, per-vendor fixes). On iOS this entire problem is replaced by a different one: no Vulkan, so the D3D→Metal translation layer (DXMT-class) becomes the single most important and most fragile component.
- Steam integration has two viable models: (a) run the real Windows Steam client headless inside the prefix (Madeira Dock/BCD Dock; Winlator "Steam client startup fixes" show this is finicky), or (b) a reimplemented Steam client that downloads depots and handles Cloud saves (Pluvia/GameNative/BCD's own downloader). DRM-protected titles need the real client or a DRM wrapper; GameNative's "DRM support" was the differentiator over Pluvia.
- On-screen control systems in this space share a design: element types (button/dpad/stick/trackpad/range), bindings to key/mouse/gamepad, per-game profiles stored as portable files with resolution-independent coordinates, and an in-place transparent editor.

### Gaps
- GameHub's internal architecture (translator, Wine version, X server or compositor) is undisclosed (closed source); only its marketing (FSR 3 frame gen, Steam downloads) is public.
- Could not retrieve the official GameNative GitHub repo (404 at GameNative/GameNative) — exact Wine/Box64/FEX versions and how DRM is handled remain unconfirmed.
- No controlled, reproducible FPS benchmarks exist for Winlator-class apps on named chips; all numbers are community/YouTube.
- Did not find documentation of how Winlator's upstream X server is implemented beyond release-note hints ("direct rendering on XServer and Turnip Vulkan WSI X11").

## KQ4. iOS UX/system layer: controllers, on-screen controls, keyboard/mouse, display (MetalFX, aspect, external display, ProMotion)

### Takeaway
Apple's GameController framework gives everything needed for a runtime: `GCController` for pads (DualSense adaptive triggers/haptics via `GCDeviceHaptics` + CoreHaptics), `GCKeyboard.coalesced`, and `GCMouse` which delivers **relative deltas only** (by design) with `prefersPointerLocked` honored only when the scene is **full-screen and foregroundActive**. Madeira/BCD already route pads to Wine via XInput and offer per-game DirectInput and controller→keyboard/mouse modes. Non-mirrored external display output from an iPhone app is officially supported (noninteractive external-display scene; iOS 27 requires registering a `UISceneAccessory`), and iPhone 17 Pro outputs up to 4K HDR via native DisplayPort over USB-C. MetalFX spatial/temporal upscaling is available from iOS 16.

### Cited Findings

**Controllers and haptics**
- `GCDeviceHaptics` (iOS 14+): "create a haptic engine with a specified locality" via `createEngine(withLocality:) -> CHHapticEngine?`; use `supportedLocalities` to detect controller haptics (the engine's `supportsHaptics` refers to the device, not the pad). — [Apple: GCDeviceHaptics](https://developer.apple.com/tutorials/data/documentation/gamecontroller/gcdevicehaptics.md)
- Precedent mapping into Wine: Madeira passes "Bluetooth controllers via XInput"; 0.1.3 added per-game "DirectInput" toggle and "controller can act as keyboard and mouse". BCD supports "DualSense (rumble, adaptive triggers, light bar), Xbox, Switch Pro, and MFi", plus a controller-to-keyboard-and-mouse mode and controller navigation across all screens. — [Madeira releases](https://github.com/willfaust/madeira/releases); [BCD README](https://github.com/thebcd69/bcd-games)
- Winlator 11.2 added an "XInput extension for raw input"; 11.1 reworked gamepad input and added "gamepad model selection"; 11.0 added multiple controllers + vibration; 8.0 added DirectInput/XInput selection. — [Winlator releases](https://github.com/brunodev85/winlator/releases)

**On-screen virtual controls (best-practice sources)**
- Winlator `.icp` profiles: element types BUTTON (toggle option, shapes), D_PAD, RANGE_BUTTON (scrollable key strip), STICK (dead zone, sensitivity; keys or gamepad axes), TRACKPAD (cursor with acceleration); fractional screen coordinates; per-shortcut profile assignment; global overlay opacity; "duplicate a close profile and adjust". — [Winlator input-controls docs](https://mintlify.wiki/brunodev85/winlator/controls/input-controls)
- Delta `.deltaskin`: ZIP with `info.json` + PDF/PNG assets; `representations` per device (`iphone.standard|edgeToEdge`, `ipad.standard|splitView`) × orientation; `mappingSize` in points (e.g., 414×896 edgeToEdge); `items` with `inputs`, `frame`, `extendedEdges` (touch padding); `screens` with `inputFrame`/`outputFrame` and CoreImage `filters`; `translucent`; `debug` overlay; guidance: map buttons exactly then add padding via `extendedEdges`, extend edge targets to the screen edge, keep `outputFrame` aspect equal to `inputFrame`. — [Delta skin docs](https://noah978.gitbook.io/delta-docs/skins)
- Madeira: "customizable on-screen touch controls"; BCD: touch-controls editor and "touch gamepad that survives the in-game keyboard". — [Madeira README](https://github.com/willfaust/madeira); [BCD README](https://github.com/thebcd69/bcd-games)

**Keyboard and mouse**
- `GCMouse` available iOS/iPadOS 14+; discover via `GCMouseDidConnect`/`GCMouseDidBecomeCurrent`, `GCMouse.current`, `GCMouse.mice()`; read `mouseInput` profile. — [Apple: GCMouse](https://developer.apple.com/tutorials/data/documentation/gamecontroller/gcmouse.md)
- WWDC20 "Bring keyboard and mouse gaming to iPad": `mouseMovedHandler` values are "the delta or change in input value since the last input was received... It is not the current X and Y position of the mouse and screen coordinates, and that's intentional"; no pointer-position polling — app owns its cursor, acceleration, edge handling; `GCKeyboard.coalesced` merges all keyboards (cannot distinguish); keyboards expose buttons only; polling is O(1), non-blocking, thread-safe; UIKit indirect-input APIs (iOS 13.4) recommended for optionally-fullscreen games, GCMouse/GCKeyboard for fullscreen games with custom pointers. — [WWDC20 10617 transcript](https://nonstrict.eu/wwdcindex/wwdc2020/10617/)
- `prefersPointerLocked` (iOS 14+): system may not honor; conditions: "The scene must be full screen, not in Split View or Slide Over... must be in foregroundActive"; lock drops automatically when conditions fail; observe `UIPointerLockState.didChangeNotification`; call `setNeedsUpdateOfPrefersPointerLocked()` after changes. — [Apple: prefersPointerLocked](https://developer.apple.com/tutorials/data/documentation/uikit/uiviewcontroller/prefersPointerLocked.md)
- SDL's iOS backend: "Only lock the pointer for mouse relative mode, there isn't really a concept of grab and confinement on iOS"; relative motion sent from GCMouse handler only in relative mode. — [SDL commit mirror](https://cdn05042023.gitlink.org.cn/zinface/SDL/commit/11ae43ca167476070225d493a642fe6e5bbb96da)
- Reported bug: GCMouse `mouseMovedHandler` "intermittently lagging"/multi-second pauses while locked (Apple Silicon report). — [Apple Dev Forums 708693](https://developer.apple.com/forums/thread/708693)
- Browser Pointer Lock API still unsupported on iOS as of 2024 (WebKit bug), relevant only as evidence that GCMouse is the sole raw-delta path. — [WebKit bug 216621](https://bugs.webkit.org/show_bug.cgi?id=216621)
- Winlator 10.0 added "pointer capture" and a per-profile cursor-speed multiplier. — [Winlator releases](https://github.com/brunodev85/winlator/releases)

**Display, upscaling, external output**
- iPhone 17 Pro display 2622×1206 (≈2.17:1, i.e., ~19.5:9), ProMotion up to 120 Hz. — [Apple Tech Specs 125090](https://support.apple.com/en-us/125090)
- MetalFX: iOS 16+; "upscale a relatively low-resolution image to a higher output resolution in less time than it takes to render directly"; `MTLFXTemporalScaler` (needs color+depth+motion) and `MTLFXSpatialScaler` (color only); Metal 4 variants `MTL4FXTemporalScaler`, `MTL4FXSpatialScaler`, `MTL4FXFrameInterpolator`, `MTLFXTemporalDenoisedScaler`; create scalers at launch or on resolution change. — [Apple: MetalFX](https://developer.apple.com/tutorials/data/documentation/metalfx.md). Forum: denoised scaler supported on Apple9+ GPU family; conflicting reports about A17 Pro `supportsMetal4FX` returning true but init crashing (unverified). — [Apple Dev Forums 819276](https://origin-devforums.apple.com/forums/thread/819276)
- External display API: "When an external display connects, the system mirrors your app's primary display, or... presents your app's interactive windows" (iPad); apps present distinct content by attaching windows to a `UIWindowScene` with role `windowExternalDisplayNonInteractive` ("spans the full screen"); Apple's own example: "a game might show its content on a connected display and show game controls on the built-in screen" (illustrated with an iPhone); **"Beginning in iOS 27, your app receives a scene with the windowExternalDisplayNonInteractive role only after it registers a scene accessory"** (`UISceneAccessory.externalNonInteractive(sceneConfiguration:)` registered on a view controller); earlier releases connected it automatically; you may change `UIScreenMode` (`availableModes`) only for the noninteractive external scene; obtain `UIScreen` via `windowScene.screen`. — [Apple: Presenting content on a connected display](https://developer.apple.com/tutorials/data/documentation/uikit/presenting-content-on-a-connected-display.md)
- iPhone 17 Pro port: "USB 3 (up to 10Gb/s)" (10Gb/s cable required), DisplayPort; **"Up to 4K HDR through native DisplayPort output over USB-C or USB-C Digital AV Adapter"**; AirPlay up to 4K HDR to Apple TV. — [Apple Tech Specs 125090](https://support.apple.com/en-us/125090)
- iPhone 15 precedent: USB-C DisplayPort drives displays up to 4K60; included cable is USB 2 only. — [MacStories](https://www.macstories.net/linked/iphone-15-usb-c-and-external-displays/); [9to5Mac](https://9to5mac.com/2023/09/16/iphone-15-usb-c-external-displays/)

### Inferences
- A Wine display/input driver on iOS (the "winios.drv" pattern) should consume GCMouse deltas when the game requests relative mode (DirectInput/RawInput/ClipCursor-style capture) and UIKit pointer events for absolute mode — mirroring SDL's split. Since pointer lock requires fullscreen foregroundActive, any overlay UI (settings panels) will transiently break lock; design the overlay as in-scene views, not separate scenes.
- Feeding Wine: Madeira's "via XInput" plus a DirectInput toggle implies a custom XInput/DirectInput provider in the prefix rather than a HID bus emulation; the report writer should present both options (custom `xinput1_x.dll`/dinput provider fed from GCController vs a winebus.sys-style HID backend) — only the former is evidenced in precedents.
- External display: the noninteractive scene lets the phone screen become the controller/touch surface while the game renders full-screen on a TV/monitor at up to 4K — Apple explicitly illustrates exactly this. On iOS 27 the app must register a `UISceneAccessory` or it will never get the external scene.
- MetalFX spatial upscaling can be applied at present time on the final swapchain image independent of the game (no motion vectors needed), making "render at 720p, upscale to 1206p/4K" a feasible runtime-level feature; temporal needs game depth/motion and is not generally available through a D3D translation layer.

### Gaps
- No Apple document retrieved on ProMotion frame pacing for Metal apps (CADisplayLink preferredFrameRateRange) — not searched.
- No public account of how Madeira/BCD implement the Wine side of input (XInput DLL vs HID) beyond the "via XInput" statement.
- Did not verify MetalFX device-family requirements for A-series phones (Apple's feature set tables not fetched).
- No source on whether `prefersPointerLocked` works on iPhone with a Bluetooth mouse when AssistiveTouch is the enabling path; the Apple doc lists iOS and iPadOS availability but the WWDC session discusses iPad only.

## KQ5. Storage and content: install sizes vs tiers, import paths (Files/UIDocumentPicker/File Sharing/USB drives), keeping a Wine prefix in the container, backup exclusion, filesystem case sensitivity

### Takeaway
Precedents keep the Wine prefix and game files inside the app container (which survives re-signing/reinstall), download games directly via Steam depot integration (Madeira/BCD) with VC++ runtime and Wine Mono fetched at runtime for licensing reasons, and need the full install size on the 256 GB–1 TB device. iOS uses the case-sensitive APFS variant, so Wine must do case-insensitive lookups in userspace (historically a measured CPU hotspot in large directories). iPhone 17 Pro supports USB 3 (10 Gb/s) and USB drives (APFS/exFAT/FAT32/HFS+, not NTFS) in the Files app; `UIFileSharingEnabled` exposes Documents via Finder/Files; `isExcludedFromBackupKey` keeps multi-GB prefixes out of iCloud/Finder backups.

### Cited Findings
- BCD: "Each game needs its full install size on the device"; downloads continue in background on iOS 26; VC++ runtime ("after accepting Microsoft's license") and Wine Mono from WineHQ downloaded at runtime, not shipped. — [BCD README](https://github.com/thebcd69/bcd-games)
- Madeira: "Games and saves are kept across reinstalls"; only Steam import documented (no local file import described); Steam Cloud saves synced at app start and before launch, with backup before replacement. HeldGames: "The app container survives reinstallation, so Wine prefixes and save files are kept." — [Madeira README](https://github.com/willfaust/madeira); [HeldGames](https://heldgames.com/guides/madeira-windows-games-iphone)
- Madeira 0.1.1 fixed "the missing `AppData\LocalLow` folder" and loaders for "unaligned data sections, missing relocation data" — prefix-layout bugs discovered through real games. — [Madeira releases](https://github.com/willfaust/madeira/releases)
- iPhone 17 Pro capacities 256 GB / 512 GB / 1 TB (Pro Max adds 2 TB); USB 3 up to 10 Gb/s with a 10 Gb/s cable. — [Apple Tech Specs 125090](https://support.apple.com/en-us/125090); [Wikipedia](https://en.wikipedia.org/wiki/IPhone_17_Pro)
- External drives: attach via the charging port; drive must have a single data partition formatted **APFS, exFAT, FAT32, or macOS Extended**; access via Files → Browse → Locations, or from a supported app's document browser; NTFS not readable. — [Apple iPhone User Guide](https://support.apple.com/en-lk/guide/iphone/external-storage-devices-iph95baac91f/16.0/ios); [Tom's Guide](https://tomsguide.com/how-to/how-to-use-an-external-storage-device-with-iphone)
- `UIFileSharingEnabled` exposes the app's Documents directory to Finder/iTunes and Files ("On My iPhone"); `LSSupportsOpeningDocumentsInPlace` enables in-place opening with security-scoped URLs. — [Apple: UIFileSharingEnabled](https://developer.apple.com/documentation/bundleresources/information-property-list/uifilesharingenabled) (page body did not render; description from fetch summary — verify)
- `isExcludedFromBackupKey` (iOS 5.1+): "exclude cache and other app support files that aren't necessary in a backup. Set this property each time you save a file because some common file operations cause this property to reset to false." — [Apple: isExcludedFromBackupKey](https://developer.apple.com/tutorials/data/documentation/foundation/urlresourcekey/isexcludedfrombackupkey.md)
- Feather signer offers "enabling Files app support" as a signing-time patch (i.e., injecting UIFileSharingEnabled into third-party IPAs). — [Feather README](https://github.com/khcrysalis/Feather)
- APFS on iOS is **case-sensitive**: "In iOS 10.3, the case-sensitive variant of APFS is used"; macOS default is case-insensitive; the case-sensitive variant is normalization-preserving and normalization-sensitive. — [Eclectic Light 2017](https://eclecticlight.co/2017/04/07/apfs-and-macos-10-13-many-apps-and-tools-will-need-to-be-revised/); [mjtsai](https://mjtsai.com/blog/2017/06/27/apfs-native-normalization)
- Wine on case-sensitive filesystems: when an exact match fails, "wine scrolls through the entire directory, converting every filename to utf8 and doing a case-insensitive comparison"; a 2006 bug attributed ~88% of CPU in a slow InstallShield copy to this; "it is hard to prove a case-insensitive name doesn't exist." — [Wine bug 3817](https://www.winehq.org/pipermail/wine-bugs/2006-July/035376.html)
- Free Apple ID sideloading: Apple "limits active sideloaded apps to three" (BCD); AltStore FAQ: "up to 10 App IDs at a time", each expiring after one week. — [BCD README](https://github.com/thebcd69/bcd-games); [AltStore FAQ: App IDs](https://faq.altstore.io/altstore-classic/app-ids.md)

### Inferences
- A 256 GB iPhone realistically holds a handful of modern AAA installs (50–150 GB each) alongside iOS; the runtime should expose per-game size, Steam DLC selection (as BCD does) and a "delete shader cache / Wine prefix" path. Storing the prefix under `Library/Application Support` with `isExcludedFromBackupKey` avoids multi-hour iCloud backups; Documents (user-visible via File Sharing) is the natural import drop-zone for non-Steam games and DRM-free installers.
- Case sensitivity: because iOS APFS is case-sensitive, a Wine prefix created on iOS will hit the same directory-scan fallback as Linux ext4 without casefold; games with large asset directories and mixed-case paths are the ones to profile. (iOS does not expose an ext4-casefold equivalent; a userspace case-folding cache in the runtime's file layer is the obvious mitigation — inference, no precedent found.)
- Importing from a USB drive goes through `UIDocumentPickerViewController`/Files; USB 3 at 10 Gb/s makes 100 GB copies feasible (~minutes), unlike USB 2 base iPhones.

### Gaps
- No source on real-world install-copy throughput on iPhone 17 Pro over USB 3.
- No precedent documents a local (non-Steam) game-import UX on iOS (Madeira's README describes Steam only; BCD adds GOG/Epic downloads).
- Did not find Apple documentation confirming whether iOS 26 still mounts the data volume case-sensitive (the 2017 sources are the only explicit statements; nothing suggests a change).

## KQ6. Distribution and update tooling for a non-App-Store app; JIT-enablement UX; App Store policy 2024–2026 (4.7, UTM SE, iDOS, StikDebug)

### Takeaway
A JIT-dependent Windows runtime cannot ship on the App Store: guideline 2.5.2 forbids executing downloaded code, and even though 4.7 was amended (Aug 2024) to let "retro game console and PC emulator apps" download games (UTM SE approved ~2024-07-13, iDOS 3 soon after), UTM SE had to drop JIT to get in. Precedents therefore distribute via sideloading (AltStore/SideStore source JSON for OTA updates; 7-day free-ID re-sign vs 1-year paid), get JIT through a debugger attach (StikDebug — AGPL, pulled from the App Store Dec 2025 after the developer's account was terminated — or an in-app helper built on the same `idevice`/StikJIT approach), and fight iOS 26.x regressions (26.4 removed the offline airplane trick; 26.6/27 work with few apps).

### Inferences
- There is no App Store door for a JIT-based x86 runtime under current 2.5.2/4.7, and the StikDebug account termination (Dec 2025) signals Apple will act against JIT enablers even when the app itself passed review. An interpreter-only build (UTM SE-style) would be App Store-eligible under 4.7 "PC emulator apps" but useless for games.
- The most robust distribution for a target user with a paid developer account: Xcode/`idevice`-based install with a 1-year profile, in-app JIT helper (PID-attach via app extension), plus an AltStore-compatible `source.json` for update notifications. For free-ID users, the 7-day re-sign, 3-active-app and ~10-App-ID limits make LiveContainer + SideStore the de-facto workaround, at the cost of sandbox isolation and (per LiveContainer) entitlements not applying — which interacts badly with `increased-memory-limit`.
- JIT availability is version-fragile: iOS 26.0 → 26.4 → 26.6 → 27 each changed the picture within one year; the runtime must gate on a reliable "JIT is live" probe and ship rapid updates, as Madeira did (four releases in three days).

### Gaps
- Apple's stated reason for terminating the StikDebug developer account is not public.
- Technical mechanics of the iOS 26 JIT break (TXM/debugger memory-permission changes) are only described in a secondary Chinese write-up; no authoritative security write-up found.
- The exact StikDebug→third-party-app IPC (URL scheme or otherwise) is undocumented; only the XCFramework/app-extension/PID pattern is described.
- Could not retrieve AltStore's "3 active apps" rule from AltStore's own FAQ (only the 10-App-ID rule); the 3-app figure comes from BCD and Notebookcheck.

## KQ7. Effort estimation: team size / time reported by comparable projects, and the biggest time sinks

### Takeaway
Every comparable project is a one-to-few-person effort measured in years: Winlator = one developer since Aug 2023 (3+ years, still "beta" quality on new GPUs), Hangover = two founders since 2016 reaching 11.0 only in Jan 2026, Whisky = one student 2023–Apr 2025 who quit, Madeira = one author + ~6 credited contributors producing ~1,000 commits (with explicit heavy AI assistance) to go from private work to a public 0.1.0 in roughly two months of visibility in 2026 — but only by forking FEX/Wine/DXMT so heavily that upstream checkouts won't build. The recurring time sinks are: the x86→host translator integration (memory model, 16 KB pages/W^X/JIT plumbing), the graphics translation layer and its per-game bugs, Steam client/DRM, loader/prefix hygiene, and input mapping.

### Cited Findings
- Winlator "started as a solo effort by developer brunodev85 and stayed niche for years"; first release Aug 2023; v11.2 Aug 2026; development paused/resumed in Apr–May 2025. — [tech-insider](https://tech-insider.org/ie/winlator-setup-2026/); [Grokipedia](https://grokipedia.com/page/Winlator); [Winlator releases](https://github.com/brunodev85/winlator/releases)
- Hangover: started 2016 (André Zwing, Stefan Dösinger); multiple architecture rewrites (Classic 0.4–0.6.5 → WOW64 0.8.1–9.19 → 11.0 Jan 2026 dropping QEMU). — [Hangover README](https://github.com/AndreRH/hangover); [Phoronix](https://phoronix.com/news/Hangover-11.0-Released)
- Whisky: student developer, unpaid, lost interest/time; shut down April 2025; successor Mythic may continue. — [OSNews](https://www.osnews.com/story/142112/whiskey-developer-throws-in-the-towel-suggests-to-just-buy-crossover-instead/)
- Madeira: 1,027 commits; author Will Faust plus credited contributors Nick, Jfishin, Jesse, Dan Perks and others; "The forks contain a lot of AI-assisted work"; requires own forks of FEX, Wine, DXMT, madeira-dock; "Some inputs, such as toolchains, are not in the repository." Described as "weeks old" on 2026-09-11; 0.1.0 2026-10-01; 0.1.1–0.1.3 within 2 days fixing iOS 26 Metal shader library version, free-ID install breakage, loader bugs, JIT UX. — [Madeira README](https://github.com/willfaust/madeira); [HeldGames](https://heldgames.com/guides/madeira-windows-games-iphone); [Madeira releases](https://github.com/willfaust/madeira/releases)
- BCD fork: 946 commits, alpha, "Many games run, many do not yet"; auto-tune suggests fixes after crashes; per-game recommended settings fetched from a list. — [BCD README](https://github.com/thebcd69/bcd-games)
- Winlator release notes show the recurring churn areas: Turnip/Vortek driver fixes nearly every release; Steam client startup fixes (10.1, 11.1); gamepad rework (11.1, 11.2 input lag fix); XServer black-screen fix; Wine Mono/Gecko fallback URLs. — [Winlator releases](https://github.com/brunodev85/winlator/releases)
- Android 8 Elite status in May 2026: three years in, upstream Winlator still does not run out of the box on the newest Adreno. — [XDA](https://www.xda-developers.com/tried-playing-pc-games-only-thing-worked-was-community-rebuild-controversial-app/)
- FEX upstream: MIT; ARM64 Linux only; needs ARMv8.0-a + FEAT_FP/FEAT_CRC32; per-app config to skip "costly memory model emulation"; experimental code cache "to minimize in-game stuttering"; repo contains AGENTS.md/CLAUDE.md/CONTRIBUTING.md (Madeira says FEX does not accept AI-generated contributions). — [FEX README](https://github.com/FEX-Emu/FEX); [Madeira README](https://github.com/willfaust/madeira)
- DXMT upstream (LGPL-2.1, macOS-targeted, has arm64ec build files) and Wine (LGPL-2.1) are the integrable upstreams; Madeira's GPL-3.0 glue and its GPL'd fork changes are not. — [DXMT](https://github.com/3Shain/dxmt); [Madeira README](https://github.com/willfaust/madeira)

### Inferences
- For an original-code project targeting one device class (iPhone 17 Pro/iOS 26–27) with upstream FEX + Wine ARM64EC + DXMT integrated (not forked wholesale), a realistic planning horizon based on precedents is: 2–4 months to a "cube renders, 2D DX11 indie game runs" milestone for a strong 1–2 person team (Madeira's visible trajectory), 6–12 months to a BCD-level alpha with Steam, controllers, and a few dozen titles, and open-ended ongoing maintenance against iOS point releases (JIT regressions arrived at 26.4, 26.6, 27 within a year). This is a derived estimate, not a sourced one.
- Largest expected sinks in order, from precedents: (1) JIT/W^X/debugger plumbing and its iOS-version churn; (2) porting FEX's Linux-only host layer to a single-process Mach environment (no precedent other than Madeira's non-upstreamable fork); (3) D3D→Metal correctness per game (Madeira's Metal 3.1/4.1 shader library issue, BCD's D3D12 runtime "work in progress"); (4) Steam client inside the prefix and DRM; (5) loader/prefix edge cases; (6) input mapping and on-screen controls; (7) memory pressure under the ~6 GB cap.

### Gaps
- No project published hours/person-months; all effort figures above are inferred from commit counts, release cadence and founding dates.
- Madeira's private development duration before Sept 2026 is unknown.
- No post-mortem from Madeira/BCD on which subsystem consumed the most time; the inference is from release-note content.
