# Paneport.UI.Tests

Tests of [Paneport.UI](../../src/Paneport.UI/README.md), including headless tests that run the Avalonia application without a screen (C-0011 section 1).

| File | What it tests |
|---|---|
| `TestAppBuilder.cs` | Not a test. It tells Avalonia.Headless.XUnit to start the real Paneport application on the headless platform for every `[AvaloniaFact]` and `[AvaloniaTheory]` test, and runs the tests one at a time, because `AvaloniaWarnings` uses Avalonia's global logger. |
| `ShellHarness.cs` | Not a test. It shows the shell the way the desktop head does, over the fakes from [Shared](../Shared/README.md), with the device test flavor's Developer section when a test gives it a developer page, and clicks controls, the navigation bar's buttons among them, with the mouse. |
| `AvaloniaWarnings.cs` | Not a test. It records what Avalonia logs at warning level or above, which includes every binding that fails at run time. Each headless test ends by asserting that nothing was recorded, except the forwarder's own tests and the negative controls in `ViewTemplatesTests`, which expect an exception or a binding warning. |
| `MainViewTests.cs` | The shell shows its navigation entries, marks Library and opens on it, and every page view model has its view. |
| `LibraryPageTests.cs` | The Library lists every title with its state and launch path, wraps the long name, and opens a title's details, from which Back returns, and so does choosing Library in the navigation bar. |
| `SettingsAndDiagnosticsPageTests.cs` | Settings shows the locale and the Steam state, keeps the locale choice disabled until it has loaded, and keeps a changed locale after another page was opened. Opening another section while Settings loads raises nothing. Diagnostics shows the host's values. |
| `DiagnosticsPageTests.cs` | S1.3.7: the Diagnostics page, rendered headless, shows every section, the warning for a limit far below the expected one, and a crash record until it is dismissed; no forbidden item reaches its text, though the sample profile carries a team identifier, an application-identifier prefix and a device identifier. |
| `ViewTemplatesTests.cs` | A view template never matches null ([app-shell.md](../../docs/design/app-shell.md) section 5). `ViewTemplates.For<T>` matches an instance of its type only, and choosing Developer again builds a new view for the new page. Each guard on the Settings page has Avalonia's generic `FuncDataTemplate<T>` as its negative control, which shows that the guard reaches a lookup for null. The page, shown while its settings load or with a saved locale that it does not offer, builds no application-level template for null, where the generic one is built inside the locale box and ends the layout with a `NullReferenceException`, as it ended the device test flavor on the device. Leaving Settings for each other section, the Developer one included, or choosing it again, with and without the drop-down opened first, shows the next page, logs no warning and leaves no logical parent on the view that left, where the generic one leaves the page blank; once the drop-down has been open, leaving also reaches its items. The drop-down, with its items made 34 high so that today's 13 locales overflow, recycles them, scrolled in an 812 by 375 window and turned from 390 by 844 to 844 by 390 while open, without building a template for null, where the generic one ends the layout. No template of the application or of a page matches null. No source in `src/` or `tests/device` has a generic `FuncDataTemplate<T>`, a template with the caller's match, such as the non-generic `FuncDataTemplate` or `FuncTreeDataTemplate`, outside `ViewTemplates.cs`, a type whose base list names `IDataTemplate` or an interface that extends it, or a using alias of one of these; the names come by reflection from the Avalonia assemblies that Paneport.UI references, and a planted source breaks each rule. Avalonia's generic `FuncTreeDataTemplate<T>`, which these rules allow, never matches null. |
| `HeadlessApplicationTests.cs` | The application starts on the headless platform and shows a window, and Avalonia logs no warning. |
| `AvaloniaLogForwarderTests.cs` | The forwarder of Avalonia's warnings writes an exception as its type only, keeps a binding error's property and path but not its message, and forwards nothing below warning level. The values name a local path that the test builds in memory. |
| `DependencyDirectionTests.cs` | Paneport.UI references no project other than Paneport.Core, and this test project references only Paneport.UI and its dependencies (C-0004 section 2). |
