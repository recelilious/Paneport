# tests/native

The CTest suite of the native host (C-0011 section 1). The presets `asan-ubsan` and `tsan` of [src/native](../../src/native/README.md) build it with AddressSanitizer and UndefinedBehaviorSanitizer, and with ThreadSanitizer, and the `native` CI job runs both on macOS.

| File | What it holds |
|---|---|
| `CMakeLists.txt` | Registers each case of each test program as a test of its own, `<program>.<case>`, builds the fake Wine fork as a module, generates the sources of the header test, and registers the checks of async-signal-safe calls: of the crash record writer and of the signal dispatcher's handler with `thread_role.c`, each on the objects of the test build and of the shipped build, and of the harness's guest fault handler |
| `pp_check.h` | The small assertion header: `PP_CHECK`, `PP_CHECK_EQUAL`, `PP_CHECK_TEXT`, and the runner of a program's cases |

Each case runs in a process of its own, because `pp_init` runs once per process. A test keeps its state in a context that it passes to its callbacks and threads, not in file-scope variables; only the outputs of the signal handler in `test_crash_record.c`, and in the signal tests the stand-in, the plain handler's outputs and the hold time of the crash record writer's hook in `test_signal_chain.c`, the program's path, which signal handlers, the hook and child processes reach without an argument, the fake platform of `jit_test_support.h`, which the JIT provider keeps for the life of the process, the fake Wine fork's state, which stands for the fork's own process-wide state, and what the host's callbacks saw in `test_session.c`, one record for the one pair of callbacks of each case's process, are static, as those tests' documented singletons (C-0010 section 3); `test_thread_control.c` keeps its path for its child the same way. A case that ends by a signal runs that part in a child process of its own program, which it starts with `posix_spawn`. A case that cannot run in one of the builds, or on the machine, prints `Skipped: ` and its reason as the first line of its output, and CTest reports it as skipped: the two cases of `test_signal_guest.c` that need a fault inside a handler, which ThreadSanitizer's run cannot deliver, and `test_thread_control.destroyed_request_fails_as_ended` on a Mac with System Integrity Protection enabled, which refuses the calls to the test's own port. The `native` CI job sets `PANEPORT_EXPECT_SIP_DISABLED` to 1, and that case then fails instead of skipping ([signals.md](../../docs/design/signals.md) section 10). The tests keep no personal data, and make their temporary folders at run time.
