# tools

C# file-based tools that check the repository and build its release artifacts (C-0004 section 3, C-0011 section 2). Each tool is one file, which may include the source files of `Shared/`, uses only the base class library, and runs from the repository root with the SDK that `global.json` pins.

| Tool | What it checks or builds | Configuration |
|---|---|---|
| `ScanPersonalData.cs` | Personal data in `docs/evidence/`, `compat/` and `tests/`, and files that C-0002 section 6 forbids anywhere | `eng/personal-data-allow-list.json` |
| `CheckCompat.cs` | The compatibility data of C-0011 section 1, so far `compat/ios-builds.json`: it must match `compat/schema/ios-builds.schema.json`, through a validator of our own for exactly the JSON Schema keywords that the schema uses, each only in the forms that it implements, which refuses a schema with any other keyword or another form of a keyword's value; with a `$schema` other than draft 2020-12, or a `$schema` or `$id` below the root; with a `title`, `description` or `$id` that is not a string; with a `required` list that names a member twice; and with a member that appears twice; a build and a model appear together in one entry only; and every evidence record that an entry names exists. The title files of `compat/titles/` join with M8.3 | `compat/schema/ios-builds.schema.json` |
| `CheckLicenses.cs` | That every package, tool, action and submodule is covered by the register in C-0003 section 6 | `eng/license-map.json` |
| `CheckToolchain.cs` | The installed SDK against `global.json` and the macOS jobs' runner image against `eng/toolchain.json`; with `--ci-tools` also the tools of the `checks` job, with `--xcode` Xcode, with `--ios-workload` the installed iOS workload set, with `--cmake` CMake, with `--llvm` clang-format and clang-tidy, and with `--fork-tools` the build tools of the forks (C-0009 section 2) | `global.json`, `eng/toolchain.json`, `.github/workflows/` |
| `ScanPackage.cs` | App packages, such as the `.ipa` files of the `ios` job and of a release: the whole scan of C-0009 section 6 (M9.1). It fails on a provisioning profile; on a team identifier or an application-identifier prefix in a property list or in a code signature; on a UDID, an ECID, a serial number, an e-mail address or a local path in any text, property list or string inside a binary of the package, or in a text file given with `--text`, unless the allow-list excuses that hit by file and by the SHA-256 of its text; with `--entitlements`, on a signature that is not ad hoc or that only the linker made, and on entitlements of the executable other than the declared ones; on debug symbols; on a file of a kind that C-0009 section 4 excludes; and on the text that `--build-path` names, in any file. It also fails on a property list, signature or DER that it cannot read, on a package without an app, and on a package that it cannot read. It lists the entitlements it finds, and never prints a matched value ([release-engineering.md](../docs/design/release-engineering.md) sections 9.4 and 9.5) | `eng/release/scan-allowlist.json`; the packages are its arguments |
| `GenerateNotices.cs` | Writes the third-party notices of an app bundle into its `licenses/` folder before it is signed, and into a build output folder: `THIRD_PARTY_NOTICES.md`, the license texts and the index of the licenses screen (C-0003 section 3, C-0009 section 6). It attributes every file of the bundle to Paneport or to register components, the main executable to the .NET runtime, .NET for iOS and every package of the app's lock file, and fails on a component that the register lacks or marks Under review, Forbidden or Tool, on a missing license text, on missing full terms of LGPL-2.1, Apache-2.0 or Unicode-3.0, on a package license that the register row does not name, on a dropped Apache-2.0 NOTICE file, on an FTL component without its credit and on an LGPL component other than SteamKit2 in the main executable. A text that no package ships comes from `raw.githubusercontent.com` at a full commit: the `ios` job fetches it into `build/upstream/`, and the tool, which never uses the network, checks its SHA-256. A file that it cannot attribute, and a text that has no source yet, are warnings with `--mode ios`, as the `ios` job runs it, and failures with `--mode release` | `eng/release/bundle-components.json`, `eng/license-map.json`, the register, `LICENSES/MIT.txt`, `build/upstream/` |
| `ReleaseVersion.cs` | The version rules of a release and its notes (M9.1): from a `v*` tag, the mode, release or dry run, `CFBundleShortVersionString` and the build number, the number of commits in the tagged commit's history; it refuses a malformed tag, a shallow checkout, and in release mode a tag off `main` or without `docs/releases/<tag>.md`. `--check-app` checks both keys in a built `Info.plist`, and `--compose` writes the body of the draft release from the notes, with the build line, the sources table and the checksums, and in release mode refuses a gate in scope that has not passed or been waived, an empty list of known issues and a placeholder left over | `docs/releases/`, `docs/evidence/README.md` |
| `ArchiveSources.cs` | The source archives of a release (M9.1): this repository at the tag and every submodule at its recorded revision, with the fork's own submodules unless they are marked `update = none`, each fetched over https without credentials, which in release mode fails on a private repository or a revision that is not pushed; it checks that the archive of each LGPL component with a `source` pin is there, and writes the source list that `ReleaseVersion.cs` reads | `.gitmodules`, `eng/release/bundle-components.json` |

Run a tool, or its self-test over synthetic fixtures:

```bash
dotnet run tools/ScanPersonalData.cs
```

```bash
dotnet run tools/ScanPersonalData.cs -- --self-test
```

`ScanPackage.cs` takes the packages to scan as its arguments, after `--`, with the options of the full scan: `--allow-list eng/release/scan-allowlist.json` and `--strict-allow-list`, `--entitlements src/Paneport.iOS/Entitlements.plist` with `--extended-virtual-addressing` when that entitlement is on, `--build-path <checkout>` and `--text <file>`. `--self-test` builds its packages in memory.

`ReleaseVersion.cs` takes `--tag <tag>`, `--check-app <bundle.app> --version <x.y.z> --build <n>` or `--compose` with the tag, mode, version, build, commit, notes, source list and checksums, and `ArchiveSources.cs` takes `--mode release|dry-run --tag <tag> --out <folder> --list <sources.json>`; the `release` workflow runs both ([release-engineering.md](../docs/design/release-engineering.md) section 9). Their self-tests build temporary git repositories.

`GenerateNotices.cs` takes a mode, the app's project and its bundle: `dotnet run tools/GenerateNotices.cs -- --mode ios --project src/Paneport.iOS/Paneport.iOS.csproj --app <bundle.app> --out build/notices/main`. With `--list-upstream` it prints `<sha256> <url>` for each text that the `ios` job fetches into `build/upstream/<sha256>` before that. Its `--self-test` builds its fixture bundles in a temporary folder.

A tool exits with 0 when its check passes, 1 when it fails, and 2 for a wrong argument or a file it cannot read. Findings name the file and the line, never the value they matched.

`Shared/` holds source files that tools include with `#:include`: `Register.cs`, the parser of the register in C-0003 section 6, and `LicenseMap.cs`, the parser of `eng/license-map.json`, which `CheckLicenses.cs` and `GenerateNotices.cs` both include; `PersonalData.cs`, the detectors of personal data, which `ScanPersonalData.cs` and `ScanPackage.cs` include; and `PropertyList.cs`, the reader of XML and binary property lists, which `ScanPackage.cs` and `ReleaseVersion.cs` include. A shared file carries no `#:` directive, because the SDK would apply it to every tool that includes the file; a tool that includes one starts with a `#!` line, which the analyzer asks of a program of several files (CA2266), so the build enforces it. `CheckLicenses.cs` checks that a tool includes only `.cs` files that git tracks directly in `Shared/`, by a plain path, and that a shared file carries no `#:` directive; it also refuses `#:ref`, and a `#:property` other than `PublishAot`.

`packages.lock.json` is the lock file that the tools share. It lists no package, because each tool turns off `PublishAot` with a `#:property` directive and uses nothing beyond the base class library. A tool that ever needs a package gets a lock file of its own, `packages.<Tool>.cs.lock.json`, which NuGet then uses in place of the shared one; `CheckLicenses.cs` requires it.

[repository-checks.md](../docs/design/repository-checks.md) describes every rule, the mapping policy, the pins, the CI jobs, how to run each check locally, and the planted-failure procedure, and [release-engineering.md](../docs/design/release-engineering.md) the notices generator.
